# SwRI AI Talk Notes (10-15 min)
## 0:00-1:00 - Title
- Open with: "I use AI to skip the tedious first pass so I can spend more time on discovery."
- Frame the talk as a practical workflow story, not an abstract AI overview.
## 1:00-4:00 - Start with a demo, not a blank page
- Show `https://lamp.space.swri.edu/cumulative-maps-all`.
- Call out the tedious gaps: map projection details, handholding, and the stuff you would not know without help.
- Emphasize that it is easier to react to a demo and say "A is better than B" than to start from a blank slate.
- Key line: AI lets us leapfrog the setup and get to "what is next?" sooner.
## 4:00-6:00 - Other examples
- `https://geoviz.space.swri.edu` MetaKernel Coverage tool.
- `https://clipperuvs.space.swri.edu/directory-browsers/gallery-native?dirKey=1` Share Drive view.
- `https://umer936.github.io/datetimepicker.js/` as a replacement for the old timepicker example.
- `https://936balloons.org/` as the fun example that still makes the point.
- Keep the point simple: these are the sorts of workflows where AI helps me get to a usable prototype faster.
## 6:00-8:00 - How I actually use it
- Show the `PHPStorm.png` screenshot to ground the story in the IDE.
- Then show `Inline_editing.png` to show selecting and refining the code changes directly.
- Message: the value is staying close to the code while AI handles the first pass.
## 8:00-9:30 - What it costs
- SwRI GitHub Copilot subscription in the IDE: about $20/month per seat.
- My usage is about 22k credits per month, roughly $110.
- The message: that is a small cost relative to the time it saves and the work it unlocks.
- This talk was 122 Credits which is about $0.61.
## 9:30-12:00 - What happens after the demo
- The next problem is connecting the idea to real data sources.
- Security matters, especially when uploads or integrations could damage data.
- Containers help package the work, ship it to better computers, and make it easier to share.
- Stress that the useful part is not just the code; it is turning it into something usable and accessible.
## 12:00-13:30 - Gotchas
- There is a lot of hype and over-optimization in the market.
- Different models are genuinely better at different tasks.
- Personal rule: Claude is often better for GUI work, then I switch back to Auto once the shape is established.
- Keep this section grounded and practical, not vendor-driven.
## 13:30-15:00 - Wrap-up
- Reiterate the takeaway: AI helps me skip the tedious first pass so I can spend more time on discovery and architecture.
- Invite questions about tooling, security, containerization, and when to switch models.
